# iPAS AI 應用規劃師刷題工具：專案規劃

最後更新：2026-07-29

## 1. 專案目標

建立一套繁體中文、手機與電腦皆可使用的靜態刷題工具，收錄 iPAS
「AI 應用規劃師」初級與中級公開題目。使用者可以依級別、科目、年度、
梯次及題目來源篩選，點選選項後立即看到答對／答錯、官方答案及詳解。

第一版以「題庫正確、來源清楚、作答流暢、方便持續擴充」為優先，不追求
大型會員系統或複雜社群功能。

## 2. 收錄範圍

### 2.1 級別與科目

初級：

- 人工智慧基礎概論
- 生成式 AI 應用與規劃

中級：

- 人工智慧技術應用與規劃
- 大數據處理分析與應用
- 機器學習技術與應用

中級第二科與第三科雖可能是應考時的選考組合，本專案仍分別收錄，讓使用者
自行選擇需要準備的科目。

### 2.2 題目來源類型

正式題庫只接受：

- iPAS 官方公開的歷次公告試題。
- iPAS 官方明確標示為「樣題」的文件。
- 官方後續公告的更正、勘誤或答案異動。

下列內容不可以混入正式題庫：

- 第三方模擬題、補習班題目或出版社題目。
- 無法追溯原始出處的網路題目。
- 由 AI 自行生成、但被包裝成考古題的題目。
- 學習指引中的一般敘述或例子，除非官方明確將其標示為題目。

若未來需要加入模擬題，必須建立獨立的 `practice` 類型，並在畫面上清楚標示
「非官方題目」，不得與正式考古題合併計算。

## 3. 「全部收錄」的定義

「全部」是指：在某一個明確的盤點截止日期以前，官方網站仍可公開取得、且
符合本文件收錄範圍的所有文件與題目。

宣稱完整收錄前，必須同時具備：

1. 一份來源清冊，列出每份官方文件、網址、日期、級別、科目、年度及梯次。
2. 每份文件的官方題數與實際匯入題數。
3. 題號連續性、重複 ID、答案及必要欄位的自動檢查。
4. 對 PDF 表格、圖片、程式碼和跨頁題目的人工目視檢查。
5. 清楚顯示盤點截止日期。

如果官方網站新增試卷，舊的「完整收錄」只代表舊截止日期的快照，不代表目前
仍然完整。更新者必須重新盤點並更新清冊。

## 4. 第一版功能

### 4.1 必做

- 初級／中級切換。
- 依科目、年度、梯次及正式試題／官方樣題篩選。
- 一次顯示一題及 A、B、C、D 選項。
- 點選後鎖定答案，立即顯示正確或錯誤。
- 第一階段顯示官方答案；第二階段完成後再提供核心觀念、完整解析及各選項說明。
- 上一題、下一題及隨機題目。
- 錯題重做。
- 使用瀏覽器本機儲存作答紀錄。
- 顯示題目來源並可開啟官方文件。
- 顯示題目及詳解的審查狀態。
- 支援手機版與鍵盤操作。

### 4.2 第一版暫不做

- 帳號、雲端同步及多人排名。
- 付費功能。
- AI 對話式助教。
- 使用者自行上傳題庫。
- 未經複核的自動出題。
- 複雜的模擬考計時與成績常模。

這些功能可在題庫及詳解品質穩定後再評估。

## 5. 建議技術方向

沿用參考專案可維護的資料分層，但只保留本專案需要的功能：

- Next.js、React、TypeScript。
- 靜態輸出，方便部署至 GitHub Pages 或其他靜態網站。
- 題目、詳解、來源清冊及畫面元件分開存放。
- 題庫依級別或科目拆檔，避免首頁一次載入全部內容。
- `localStorage` 保存錯題與作答進度。
- 由產生腳本建立題庫 manifest、數量及內容雜湊。
- 使用 Node 測試驗證資料，使用 Playwright 驗證實際點選流程。

正式實作前仍應重新檢查參考專案的授權、目前版本與可重用範圍，不直接整包複製。

## 6. 執行階段

### 6.0 兩階段交付決策

本專案目前採用「先全部題目、後全部詳解」：

- 第一階段先完成目前可確認的 715 題匯入與官方答案核對。
- 第一階段完成前，不開始批次詳解工作；現有 3 題實質初稿保留。
- 第二階段再依題庫清單完成全部詳解初稿與獨立複核。

詳細順序、數字及階段切換條件見
[題庫建置兩階段執行計畫](DELIVERY_PHASES.md)。下列階段 A～C 屬於第一階段，
階段 D 屬於第二階段。

### 階段 A：官方來源盤點

- 建立來源清冊。
- 下載或記錄官方試題、樣題及勘誤文件。
- 記錄每份文件的預期題數、答案呈現方式及特殊版面。
- 找出不同網址但內容相同的重複文件。

交付結果：可以回答「官方目前公開了哪些文件、每份有幾題、哪些尚未處理」。

### 階段 B：題目匯入

- 先以工具抽取 PDF 文字。
- 將每題轉成統一資料格式。
- 對照 PDF 頁面檢查題號、題幹、選項、答案、圖片及程式碼。
- 產生穩定且不會因排序改變的題目 ID。

交付結果：所有清冊內題目都能被程式載入，且能追溯到來源。

### 階段 C：基礎刷題介面

- 完成篩選、作答、顯示答案、前後移動及錯題紀錄。
- 正確處理重複作答與重新練習。
- 題目包含長文、表格、程式碼或圖片時仍可閱讀。

交付結果：使用者可以完整做完任一份試卷。

### 階段 D：詳解撰寫與複核

- 必須等階段 B 的固定盤點題庫全部完成後才開始批次執行。
- 依撰寫規則產生初稿。
- 逐一確認官方答案、技術概念及四個選項。
- 對時效性較高的內容記錄查核日期。
- 完成第二人或獨立複核後才能標記為 `reviewed`。

交付結果：畫面上的詳解狀態與實際複核進度一致。

### 階段 E：驗證與發布準備

- 執行資料完整性、建置、程式碼檢查及瀏覽器測試。
- 在手機與桌面尺寸實際作答。
- 比對來源清冊、題庫 manifest 和畫面顯示的總數。
- 檢查正式網站是否能開啟官方來源連結。

部署、推送或公開發布必須另外取得專案負責人的明確指示。

## 7. 第一版驗收標準

資料：

- 清冊內每份官方文件都有處理狀態。
- 已收錄文件的題數與官方文件一致。
- 題號沒有非預期缺漏，題目 ID 沒有重複。
- 每題都有級別、科目、題幹、選項、官方答案及來源。
- 特殊計分、複數答案或官方更正有獨立欄位，不硬塞成一般單選題。

詳解：

- 每題至少說明正確答案及錯誤選項原因。
- 自行撰寫內容不標示為官方解析。
- 已標示 `reviewed` 的題目都有複核者、日期及依據。
- 尚未完成的內容誠實標示 `missing` 或 `draft`。

介面：

- 選項可以點選，第一次選擇後不能偷改答案。
- 答錯時會明確顯示錯誤選項、正確答案與詳解。
- 答對時也可閱讀詳解。
- 重新整理頁面後仍保留本機進度。
- 錯題篩選只包含實際答錯的題目。

品質：

- 自動測試通過。
- Playwright 完成至少桌面及手機主要流程。
- 產生後題庫數量與來源清冊一致。
- 沒有把第三方題目誤標為官方題目。

## 8. 題庫進度的內部紀錄

題庫蒐集、匯入與複核進度只記錄在 `docs/SOURCE_INVENTORY.md`、
`docs/HANDOVER.md` 與結構化來源資料中，不在刷題網站公開顯示進度卡片。
內部紀錄統一使用以下格式：

> 題庫盤點截止：YYYY-MM-DD  
> 官方文件：已處理 X／Y 份  
> 官方題目：已匯入 X／Y 題  
> 官方答案已核對：X 題  
> 詳解初稿完成：X 題  
> 詳解已複核：X 題

除非上述數字都有可重算的證據，不使用「最完整」、「全部完成」或「100% 正確」
等無法驗證的描述。
